# SUFY Image2 Skill Design

Date: 2026-08-17

## Objective

Publish an installable Agent Skill that reproduces the image-generation capabilities currently used by `image.ctikki.com` through the LTS4AI `SF-gpt-image-2` relay. A user should be able to install the skill, provide an API key at runtime, and ask an Agent to generate or edit images without manually constructing provider requests.

## Naming

- GitHub repository: `CTctikki/sufy-image2`
- Skill name: `sufy-image2`
- Provider base URL: `https://api.lts4ai.com/v1`
- Provider model: `SF-gpt-image-2`
- Display name: `SUFY Image2`

The public name follows the requested SUFY Image2 branding. The documentation must state that the actual LTS4AI model identifier is `SF-gpt-image-2`.

## Supported Capabilities

1. Text-to-image generation through `POST /v1/images/generations`.
2. Image-to-image editing through multipart `POST /v1/images/edits`.
3. One to twelve reference images per edit request.
4. The image formats accepted by the current site: JPEG, PNG, GIF, and WebP.
5. The current site's aspect-ratio choices: Adaptive, 1:1, 16:9, 21:9, 4:3, 3:2, 5:4, 2:1, 3:4, 2:3, 4:5, and 9:16.
6. The current site's 1K, 2K, and 4K labels and resolution mapping.
7. Up to ten generated tasks using repeated prompts or a line-based prompt queue.
8. Bounded concurrency, cancellation through process termination, provider timeouts, and retries for rate limits and transient 5xx failures.
9. Base64, data-URL, nested JSON, SSE-wrapped JSON, and remote image URL response extraction.
10. Optional model listing for credential and endpoint diagnostics.

## Explicit Limitations

- `SF-gpt-image-2` requests do not receive the UI's seed value. The skill must not claim deterministic seed support.
- The client validates a maximum of twelve references and 15 MB total input bytes, matching the current site. It does not silently upload unsupported formats.
- The client does not promise pixel-identical output or provider-side reproducibility.
- The skill does not contain, request, or publish a shared API key.

## Provider Contracts

### Text to Image

Request:

```http
POST https://api.lts4ai.com/v1/images/generations
Authorization: Bearer <api-key>
Content-Type: application/json
```

```json
{
  "model": "SF-gpt-image-2",
  "prompt": "...",
  "size": "1024x1024",
  "output_format": "png"
}
```

The request must not add legacy `n` or `response_format` fields.

### Image Editing

Request:

```http
POST https://api.lts4ai.com/v1/images/edits
Authorization: Bearer <api-key>
Content-Type: multipart/form-data; boundary=<generated-boundary>
```

Multipart fields:

- `model=SF-gpt-image-2`
- `prompt=<prompt>`
- `size=<mapped-size>`
- `output_format=png`
- repeated `image` file parts in user-supplied order

The HTTP library must generate the multipart boundary. The caller must not hard-code the `Content-Type` boundary.

### Response

The canonical response image is `data[0].b64_json`. The parser will also tolerate data URLs, nested image objects, SSE data frames, and remote URLs. Generated bytes are written to local output files, and stdout reports machine-readable JSON metadata without secrets.

## Resolution Mapping

For 1K and 2K labels, preserve the current workbench mapping:

- Adaptive or 1:1 → `1024x1024`
- 16:9, 4:3, or 3:2 → `1536x1024`
- 9:16, 3:4, 2:3, or 4:5 → `1024x1536`
- 21:9, 5:4, or 2:1 → `auto`

For 4K:

- 1:1 → `2880x2880`
- 16:9 → `3840x2160`
- 21:9 → `3840x1648`
- 4:3 → `3264x2448`
- 3:2 → `3504x2336`
- 5:4 → `3200x2560`
- 2:1 → `3840x1920`
- 3:4 → `2448x3264`
- 2:3 → `2336x3504`
- 4:5 → `2560x3200`
- 9:16 → `2160x3840`
- Adaptive → `3840x2160`, unless an edit can infer the nearest supported ratio from its first reference image

## CLI Design

The standard-library-only Python CLI will expose:

```text
python scripts/sufy_image2.py generate --prompt ... [options]
python scripts/sufy_image2.py edit --prompt ... --image file [--image file ...] [options]
python scripts/sufy_image2.py batch --prompt ... --count N [options]
python scripts/sufy_image2.py batch --prompts-file prompts.txt [options]
python scripts/sufy_image2.py models
```

Common options include ratio, quality label, explicit expert resolution override, output directory, concurrency, timeout, retries, base URL, and model. Defaults use the LTS4AI SF contract.

## Credential Safety

Credential lookup order:

1. `LTS4AI_API_KEY` environment variable.
2. Non-echoing interactive input through `getpass` when a TTY is available.
3. A dedicated stdin mode for Agents that cannot set a process-local environment variable.

The skill instructs Agents to never place keys in command-line arguments, repository files, shell history, generated metadata, or chat summaries. Exceptions and HTTP errors must never interpolate the key.

## Agent Workflow

When triggered, the Agent will:

1. Determine whether the user wants generation, editing, or a batch.
2. Ask only for missing creative inputs or the API key.
3. Keep the key ephemeral and invoke the bundled CLI.
4. Choose conservative defaults when ratio or quality is unspecified.
5. Return the generated file paths and render images when the host supports it.
6. Explain actionable provider errors without exposing credentials.

## Testing

Tests use an in-process mock HTTP server and no real API key or paid request. They must verify:

- exact JSON generation contract;
- exact multipart edit contract and repeated image order;
- absence of `n`, `response_format`, and key leakage;
- ratio and quality resolution mapping;
- reference-count, input-size, and MIME validation;
- JSON, SSE, base64, data-URL, and URL response extraction;
- retry behavior for 429 and 5xx responses;
- batch output naming and machine-readable summaries;
- CLI help and credential-source behavior.

The Skill is additionally validated with `quick_validate.py`, Python compilation, unit tests, and representative mock CLI runs.

## Distribution

The repository will be public under the MIT License. The README will include generic installation instructions for Agent Skill installers and manual installation, without claiming a single vendor-specific installer command works everywhere.

## Acceptance Criteria

- A compatible Agent can discover the Skill from its description.
- A user can provide only an API key plus a natural-language image request and receive an output image.
- Text-to-image and multi-reference editing use the exact current LTS4AI SF contracts.
- No test or repository file contains a real credential.
- All local validation passes before the public repository is created and pushed.
